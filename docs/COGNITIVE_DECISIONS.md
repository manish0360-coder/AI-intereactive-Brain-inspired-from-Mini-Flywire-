# Cognitive Engineering Decisions

These are engineering decision records for the cognitive research package. **They are not Director rulings.** Rulings stay in `research/09_decisions.md` (D-001 … D-044), and this file does not amend them.

Each record gives the context, the decision, the alternatives and the consequences. A later record may supersede an earlier one; superseded records stay in place.

---

### CD-001 — First milestone is environment–agent separation (CF-01)

- **Context.** The audit (`COGNITIVE_AUDIT.md` §6–§9) found:
  - no environment object;
  - no observation boundary;
  - reward computed by the agent;
  - four privileged map channels (L1–L4);
  - no task that hides knowledge.

  Without a test bed, no cognitive mechanism can be credited.
- **Decision.** CF-01 builds the testbed and a discriminating battery before any new mechanism.
- **Alternatives.**
  - (a) Repair the MFW internals first: wire the executive weights, remove the oracles. Rejected: there would be no way to measure the result, and it is a production edit under governance.
  - (b) Build the world-model agent first. Rejected: it has no evaluation venue.
  - (c) Reuse COG-A as is. Rejected, see CD-002.
- **Consequences.** The first new cognitive mechanism arrives in CF-03. CF-01 is infrastructure plus a scientific gate: task discriminability.

### CD-002 — New testbed package instead of extending COG-A

- **Context.** `experiments/coga/` has a working environment with hidden per-edge reliability, CRN and Q / Dyna-Q baselines. However:
  - its API is `attempt(from, to)`;
  - agents read the global `NEIGHBOURS` topology;
  - it has no observation contract;
  - its code is bound to frozen study configurations (`lock.mjs`);
  - its outcome labels are historical (ACQ-1 is void under D-035).
- **Decision.** Create `cognitive/testbed/` and `cognitive/agents/` with the reset/step contract of handbook §8. The design ideas are reused and credited: per-edge CRN streams, QB1 and DYNA semantics, and the distal-change definition for E4. No COG-A file is modified or imported.
- **Consequence.** Two environment codebases exist. COG-A stays frozen as a historical study record.

### CD-003 — Opaque, permuted action labels and relabelled nodes

- **Context.** If the action index equals a sorted neighbour id, or node ids follow generation order, the observation leaks topology.
- **Decision.** Node labels are a per-world random permutation, and exits are a per-node random permutation. Both are hidden. A test fails if more than half of the nodes have identity-ordered exits.
- **Consequence.** Agents must learn where each action leads (C2).

### CD-004 — The environment emits reward; goal entry obeys dynamics

- **Context.** MFW computes its own reward from the goal identity (audit L6), and its goal-entering move bypasses the environment (L7, the cause of ACQ-1's voiding).
- **Decision.** Reward is a property of the environment: 1 on arrival at the rewarded node. Every traversal, goal entry included, uses the same dynamics.

### CD-005 — Goal cue semantics are declared task knowledge

- **Context.** In cued tasks (E1), a model-based agent needs to know that reward is delivered at the cued node in order to plan before reaching it.
- **Decision.** The cue means "reward is delivered on arrival at this node label". Agents may use that meaning. In uncued tasks (E3) the cue is null, and the reward must be learned from experience.
- **Consequence.** E1 tests the use of learned transitions toward a stated target. It does not test discovery of where the reward is.

### CD-006 — Dependency-free, tabular first

- **Context.** "The lab stays dependency-free" (`research/external/DO_NOT_REBUILD.md`). The state spaces are small.
- **Decision.** Plain Node.js ES modules with no packages. Tabular agents only, until a task demonstrably needs function approximation.

### CD-007 — Seed domains are derived from labels, disjoint from M7 registries

- **Decision.** Seeds come from SHA-256(label). Domains are `dev`, `gate` and `confirm`. The registered M7 seed blocks, held-out ranges, MCF-1 blocks and AC38/TC-2 worlds are never used. The `gate` domain of each milestone is used once.

### CD-008 — Development gate frozen before its gate-domain run

- **Decision.** CF-01's gate parameters are frozen in `experiments/cf01/GATE_SPEC.md` and committed before the gate domain is run. The commit is local, and pushing it needs authorisation, so the freeze is evidenced by commit order and not by remote verification. This is disclosed in the results.

### CD-009 — The CF-00 audit probe is committed as evidence

- **Decision.** The runtime audit's preload, session driver and analysis live in `experiments/cf00_audit/`, so every number in `COGNITIVE_AUDIT.md` can be regenerated by one command. Raw records stay outside the repository.
