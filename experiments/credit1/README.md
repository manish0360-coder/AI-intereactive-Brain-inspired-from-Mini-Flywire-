## Pipeline writes (I-LEDGER; Gemini round 3, CRITICAL)
Writes from the episode pipeline (`PIPELINE_REPLAY`: `replayOneEpisode();`; `PIPELINE_BRIDGE`: the bridge's `recordAutonomousSuccess(`) are key-checked; no class bypasses validation.

**The rule.** Each such write must be a `set` to Q, rewards, transitions, pathSuccesses or confidence, with a well-formed key built from a consecutive pair of the episode the pipeline processed:
- **Q goal part:** GOAL_NONE (0) for replay, because the copy's `activeGoal` stays `null`; the terminal node for the bridge.
- **Single episode:** one replay call must come from one episode.

**Evidence the driver records** (observational, through `exportEpisodes()`):
- the replay candidates at the `replayBranch()` hook, which immediately precedes `replayOneEpisode()`;
- the stored bridge episodes after a call with bridge writes.

A pipeline write without evidence fails. Gate G4.7–G4.7d and mutants PL1–PL12.

**Not yet validated on real sessions.** The calibration run `calib-20261026-c144130` passed D-3 under the previous evaluator, which did not key-check pipeline writes. The corrected I-LEDGER must be validated on development sessions before freeze.

## Swap-parity check (development only; Gemini round 3, HIGH): built, NOT AUTHORIZED, NOT RUN
**The question.** Does delivering the training export of world π(w) through the swapped-store path (N1A× / N1L×, `brainWorld = π(w)`) behave exactly like delivering a byte copy of the same export through the normal own-store path? The own-path session is N1A / N1L under `SWAP_PARITY_OWNPATH`, with `brainWorld = w` and `storeSourceWorld = π(w)`. Everything else is the same: world w, seeds, tree, credit mode and mask.

**Claim limit.** A pass establishes delivery-path equivalence only. It says nothing about whether credit alignment improves learning; that is the confirmatory experiment's question.

```bash
node experiments/credit1/run_swap_parity.mjs --plan-only
```

**Plan: 60 sessions** on the existing XFER-1 development configurations of worlds 0–10:
- 20 training sessions: T_A and T_L on the π sources of worlds 0–9 (worlds 0–7, 9, 10);
- 20 swapped sessions: N1A× and N1L× on worlds 0–9;
- 20 own-path sessions: N1A and N1L under `SWAP_PARITY_OWNPATH`, each given its own byte copy of the same export.

**Pass rule.** For each of the 20 pairs:
- both sessions are valid (completed, condition integrity, map audit);
- I-CRED and I-LEDGER: PASS/PASS in A pairs, no FAIL in L pairs (the corrected pipeline-key checks included);
- the copy's sha256 equals its source export's;
- the recorded delivery paths are as planned;
- the delivered store hashes are equal to each other and to the expected masked store;
- every D-1 field and every CREDIT-1 instrument block (telemetry, I-CRED, I-LEDGER with its pipeline evidence, event classes, episodes, redirects, self-target counts) is present;
- the two records are equal everywhere except `label`, `cell`, `procedure` and the delivery source, world, file and declared source world.

Any other difference fails, and the run stops at the first failure.

**Scope.**
- The own-path procedure runs only under `SWAP_PARITY_AUTHORIZATION` in `lock.mjs`, which is `null` (the driver and the runner refuse). It is never authorized by the calibration record, and only on N1A / N1L, worlds 0–10.
- The training and swapped sessions are design cells within the calibration scope.
- No world outside 0–10, no confirmatory territory, no A+.
- Output goes to a git-ignored `data/<run>` directory (G8.1 checks it against the swap-parity lock, plan and scope).
- Gate G10.1–G10.6, G5.6b, G8.1d; mutants SP1–SP11, LS1–LS4, SC1–SC24, DG12–DG16.

## Timing diagnostic (Milestone T; T-build, owner authorization of 2026-10-28): built, NOT AUTHORIZED, NOT RUN

schema-rebuild throttle (`render/schemaMemory.js:133`), and is the loop-advanced virtual clock (variant C: t0 + 500 ms per agent
loop fired by the harness) deterministic under load for the tested sessions? `TIMING_DIAGNOSTIC_PLAN.md` is the preregistration:
matrix (125 sessions, 145 with the conditional escalation), artifacts, comparison and exclusion rules, validity and escalation
rules, and the interpretation table unchanged from the owner-reviewed design.

```bash
node experiments/credit1/run_timing_diagnostic.mjs
```

Plan-only is the default (no lock, no session). A run needs `--run --out <dir under data/>` and refuses unless
`TIMING_DIAGNOSTIC_AUTHORIZATION` in `lock.mjs` holds exactly its record; it is `null`.

**The clock.** `clock_preload.mjs` is loaded with `node --import` only for the `TIMING_DIAGNOSTIC` procedure; its configuration is
the session input's `clock` field (an invalid one makes node exit before the driver runs). The driver's guard (`clock.mjs`
`driverClockProblems`) runs before the scope check and before any runtime module: the diagnostic needs exactly the pinned preload,
its frozen marker and the installed `Date.now`; every other session refuses any clock input, node flag, marker or non-native
`Date.now`. The calibration and swap-parity runners pass no node flag, and their analyses refuse clock-bearing records.

**Claim limits.** 25 test and 5 training sessions on one machine: no universal determinism claim. No effect estimate, cell mean or
outcome summary is computed or reported; the report holds identity verdicts, differing field paths and call positions only.

**Scope.** Ten development worlds (2, 3, 6, 7, 14, 15, 21, 22, 25, 26), eight cells, A+ excluded, no confirmatory territory; the
test sessions receive byte copies of 15 SHA-256-pinned stores of `calib-20261027-cb7e015`. Output goes to a git-ignored
`data/<run>` directory (G8.1 checks it against the timing-diagnostic lock, plan and scope). Gate G11.
